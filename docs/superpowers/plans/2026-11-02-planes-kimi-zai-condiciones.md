# Planes Kimi Code y GLM Coding: compatibilidad pendiente

El catálogo de Pi instalado incluye `kimi-coding` y `zai-coding-cn`, pero eso no demuestra que los derechos de una suscripción permitan usar su API dentro de Savia para procesar licitaciones. Kimi describe Code como beneficio para programación y dirige las integraciones en productos a su plataforma de API; también exige conservar el identificador real del cliente. Sus rutas y credenciales de suscripción son distintas de Moonshot API. [Kimi Code Overview](https://www.kimi.com/en/help/kimi-code/membership-guide).

GLM Coding permite escenarios de oficina en herramientas y entornos expresamente admitidos, y enumera Pi como agente de programación. No queda establecido en esa lista que integrar el SDK de Pi en Savia autorice todos sus flujos. Además, la documentación anuncia sustituciones automáticas de varios modelos antiguos. Estas condiciones requieren verificación específica para Savia y para el modelo seleccionado. [Herramientas admitidas por Z.ai](https://docs.z.ai/devpack/tool/others), [modelos y sustituciones](https://docs.z.ai/devpack/overview) y [condiciones de herramientas de China](https://docs.bigmodel.cn/cn/coding-plan/tool/others).

Las API independientes Moonshot y Z.ai ya disponibles no representan las suscripciones de programación. No habilitar `kimi-coding` ni `zai-coding-cn`, ni presentar sus cuotas como equivalentes, hasta verificar las condiciones, el destino, la identificación del cliente, los modelos efectivos y su integración real. No se hizo inferencia ni se cambiaron credenciales.
