# Revisión previa de presentación

La revisión existente en escritorio resume los datos guardados de cierre, requisitos, documentos requeridos, vigencia registrada, oferta económica y tareas. Debe mantenerse como ayuda para revisión humana: nunca declara habilitación ni presentación. La fecha observada por SECOP solo sustituye a la guardada si está verificada.

1. Reutilizar el cálculo existente y comprobarlo con las pruebas del escritorio. Adaptar la lectura web de requisitos, soportes, certificados, RUP, tareas, oferta y fecha de cierre sin modificar esos datos.
2. Exponer una consulta privada por proyecto en D1 con aislamiento entre cuentas; probar fechas, documentos no disponibles, ofertas incompletas y estados sin fuentes.
3. Añadir una revisión es/en en el proyecto con actualización manual y acceso a las secciones pertinentes. Informar que se usan datos guardados y que no se determina habilitación ni se presenta la oferta.
4. Verificar compilaciones y pruebas focalizadas; la revisión visual sigue pendiente si el navegador local está deshabilitado. Sin inferencia ni ejecución alojada.

**Estado:** la consulta aislada por cuenta y la vista de revisión están implementadas con las reglas del escritorio. Las pruebas cubren cierre observado verificado, fechas de certificado inconsistentes o vencidas, vínculos no disponibles, requisitos pendientes y oferta inválida o guardada; la representación es/en y ambas compilaciones pasan. Las acciones llevan a las secciones existentes. La revisión visual y las pruebas interactivas siguen pendientes porque el navegador local está deshabilitado.
