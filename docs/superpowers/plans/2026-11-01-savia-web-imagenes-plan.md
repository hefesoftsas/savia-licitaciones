# Imágenes de capítulos migrados

**Objetivo:** preservar imágenes de capítulos de escritorio en la nube y permitir su visualización y exportación Word mediante el runner local, sin modificar el texto original del usuario.

**Fuentes:** el respaldo contiene `workspace/imported-images/`, `workspace/generated-images/technical-plan/` y los directorios `imported/`, `generated/` y `technical-plan-content-generation/` de cada instantánea inactiva. Los capítulos pueden contener Markdown o HTML, URLs `savia-asset` y referencias de recursos del agente en `data-sv-asset-ref`. Los archivos de agente del proyecto activo residen bajo `agent-runtime/pi/tasks/`. Las referencias ausentes, externas o no identificables deben informarse, no sustituirse silenciosamente.

**Diseño:** detectar referencias usando los parsers existentes y relacionarlas únicamente con rutas validadas del proyecto del respaldo. Conservar una identidad de origen por referencia y registrar bytes, tipo, tamaño y hash en R2/D1 bajo el proyecto importado. Usar recibos separados del plan, cargas idempotentes y el registro de staging para recuperar fallos entre R2 y D1; el limpiador debe reconocer también estas referencias antes de borrar. Exponer lectura autenticada al propietario y por concesión de tarea al runner; nunca agregar imágenes a la lista de documentos de licitación. La interfaz presenta las imágenes locales mediante rutas autenticadas, sin permitir HTML remoto no confiable. La exportación obtiene las imágenes de la instantánea autorizada y las resuelve en un directorio temporal sin alterar el texto del plan. Debe detectar cambios y avisar de imágenes que no estén disponibles. No iniciar tareas alojadas ni proveedores de IA.

**Condiciones:** preservar identificadores, texto y referencias; no buscar fuera del ZIP ni interpretar rutas absolutas, recorridos o enlaces; tratar correctamente nombres Unicode y rutas Windows; conservar una imagen compartida sin duplicados innecesarios; ninguna limpieza debe retirar un objeto vinculado. Los datos de otro proyecto o cuenta no son accesibles. La ausencia de una imagen no debe borrar el resto del capítulo ni fingir que se exportó. Migraciones anteriores y reintentos mantienen el mismo proyecto.

**Validación prevista:** respaldos reales de proyecto activo e inactivo, imágenes compartidas y referencias malformadas; fallos de R2/D1, interrupciones y cargas concurrentes; acceso cruzado y concesiones caducadas; visualización sin HTML activo; DOCX real con imagen incrustada y aviso verificable para imagen ausente; reintento de proyectos importados por versiones anteriores; suites API/runner y distribución.

**Avance:** lectura y carga de imágenes PNG/JPEG/GIF/WebP con detección de referencias ausentes, externas, inseguras o formatos no compatibles; aislamiento de documentos de pliego y limpieza de staging. El runner descarga las imágenes referenciadas mediante una concesión ligada a la versión del plan y las incorpora al Word; WebP estático se convierte a PNG y WebP animado produce un aviso. Una prueba desde un respaldo real comprueba las imágenes en el DOCX. La vista previa web interpreta Markdown y HTML mediante una lista de elementos permitidos, sin activar HTML ni cargar imágenes externas, y obtiene las imágenes del proyecto con la sesión autenticada. Si la imagen no está disponible se conserva el texto y se informa. Falta la revisión visual en navegador, deshabilitado en este entorno. SVG y otros formatos se informan como no compatibles; no se descartan silenciosamente.
