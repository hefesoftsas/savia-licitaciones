# Seguimiento posterior a la presentación en la web

La versión de escritorio en el checkout original registra presentaciones con copias del paquete y comprobante, solicitudes de observación o subsanación, tareas opcionales y resultados manuales. Las fechas de solicitudes abiertas aparecen en agenda y tablero. El usuario registra esta información; Savia no la envía a SECOP ni la considera prueba automática de presentación.

1. Crear en D1 los registros por proyecto para solicitudes y resultados. API privada por propietario y mismo origen; solicitudes con tipo, fecha opcional, notas, estado y control de versión, y tarea opcional creada en la misma transacción. Mantener el identificador histórico cuando se retire la tarea. Resultados manuales históricos sin alterar el estado oficial ni la etapa del proyecto. Probar aislamiento, fechas, concurrencia y reversión de la tarea.
2. Incorporar copia verificable de paquete, comprobante y adjuntos en R2 con reintentos y limpieza; conservar tamaño, nombre y SHA-256. No anunciar presentaciones hasta que el registro y ambas copias estén completos.
3. Integrar interfaz es/en, agenda, recordatorios y tablero; migrar datos existentes de escritorio, captura y restauración web. Probar el flujo completo y regresiones con Miniflare y el runner.

La primera etapa no representa la paridad completa y no expone una interfaz incompleta como función terminada. La captura actual de proyectos debe seguir indicando que omite otros datos hasta añadir este contenido.

**Avance:** la migración `0136` y la API guardan solicitudes y resultados manuales por proyecto. Crear una solicitud con tarea usa una transacción; el estado admite control de versión y conserva la referencia histórica si se elimina la tarea. Las solicitudes abiertas con fecha aparecen en agenda y recordatorios como información personal. Miniflare verificó dos cuentas, fechas, conflicto de versión, reversión de tarea y resultado sin modificar la etapa. Compilaron la web y el cliente; el detector de interfaz no encontró problemas. La creación y revisión aún no tienen interfaz; faltan presentaciones, archivos, migración y recuperación, tablero y revisión visual interactiva.

**Actualización:** la web ya permite crear solicitudes y resultados, cambiar el estado y consultar el historial en es/en. Los borradores participan en la protección de navegación y la migración `0137` permite reintentar creaciones sin duplicarlas; Miniflare comprobó solicitudes simultáneas, conflictos y una sola tarea. La interfaz aún no ofrece paquetes, comprobantes ni adjuntos. Siguen pendientes la migración y recuperación de estos datos, el tablero y la revisión visual interactiva.

**Adjuntos de solicitud:** cada archivo se carga como flujo a un objeto temporal con límite de 256 MiB, se calcula SHA-256 y se publica en D1 con clave idempotente solo si la solicitud y la concesión temporal siguen vigentes. Una lectura vuelve a verificar tamaño y hash y utiliza lectura condicional. La limpieza de cargas fallidas y de proyectos debe reconocer los objetos publicados. Probar aislamiento, reintentos, contenido cambiado, interrupciones y eliminación con Miniflare antes de conectar la interfaz. No habilita todavía paquetes o comprobantes de presentación.

**Avance de adjuntos:** la migración `0138` y la API permiten guardar y descargar archivos de solicitudes con longitud declarada, SHA-256, publicación idempotente y limpieza de objetos. Miniflare verificó aislamiento entre cuentas, tamaño distinto del declarado, reintentos y conflictos de contenido, alteración, fallo de D1 y eliminación del proyecto. La descarga lee el objeto para comprobar el hash y después lo entrega condicionalmente: esto implica dos lecturas y requiere medir costos y límites en Cloudflare real. La carga única sigue sujeta a los límites de solicitud del plan de Cloudflare; falta carga multipart para archivos que los superen. La interfaz, paquetes, comprobantes y respaldo siguen pendientes.

**Interfaz de adjuntos:** la pantalla permite añadir y descargar archivos de solicitudes, conservar el mismo archivo y clave al reintentar una respuesta perdida, y avisa antes de abandonar un borrador. Las pruebas verifican el contrato de carga y la representación es/en; Miniflare cubre el transporte de un archivo mediante el mismo cliente. Compilaron la web y el cliente. Falta la revisión interactiva del navegador, carga multipart, paquetes, comprobantes y respaldo.

**Presentaciones:** el registro web seleccionará dos documentos ya cargados en el proyecto y copiará cada uno a un objeto independiente en R2. El servidor calculará el SHA-256 de las copias y publicará registro y metadatos de ambos archivos juntos en D1, tras verificar que siguen siendo documentos del proyecto y que sus objetos no cambiaron durante la copia. Una clave idempotente permite reintentar sin duplicar; las copias incompletas usan la limpieza existente. La descarga verifica integridad. Una eliminación posterior de los originales no elimina las copias. Son evidencias seleccionadas por el usuario, no prueba de radicación. El límite combinado inicial es 256 MiB y no se promete una instantánea atómica D1/R2.

**Avance de presentaciones:** la migración `0139`, la API y la pantalla guardan la fecha, radicado, versión y dos copias verificadas elegidas entre los documentos del proyecto. Se admiten paquetes ZIP como archivos del proyecto sin seleccionarlos para análisis. Miniflare comprobó cuentas separadas, creaciones simultáneas idempotentes, falla transaccional, integridad, eliminación de originales y limpieza al borrar el proyecto. Se compilaron las interfaces y la representación estática se revisó en es/en. La migración y recuperación de este historial, la revisión visual interactiva y las pruebas en Cloudflare real siguen pendientes.
